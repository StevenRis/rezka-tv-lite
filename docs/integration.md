## Ограничения архитектуры

GitHub Pages размещает статические HTML/CSS/JS, но не серверный адаптер:
https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

Чтение HTML или JSON с другого домена через XHR требует разрешающего CORS-ответа:
https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS

Открытие Rezka обычной ссылкой возможно независимо от разрешения читать её из
приложения. iframe не решает CORS и не даёт управлять чужой страницей; сайт также
может запрещать встраивание. Встраивание и заголовки настоящей страницы не проверены.

## Следующий этап после телевизионного теста

1. Получить фактический User Agent, коды пульта, результат MP4 и сетевого теста.
2. Если сайт доступен в исследовательской среде, изучить реальные заголовки,
   HTML каталога, поиск и условия интеграции. Никакие внутренние endpoints сейчас
   не считаются подтверждёнными.
3. Выбрать прямой разрешённый API либо отдельный серверный адаптер, если он нужен.
   Публичный случайный CORS-прокси не использовать. Сервер не нужен для тестового UI.
4. Проверить один элемент каталога, затем один разрешённый видеопоток на телевизоре.
   Проверить HTTPS, кодеки, Range, редиректы, cookies и срок действия URL.

Авторизация, DRM, защитные проверки и ограничения доступа не обходятся. Логины,
cookies и токены в публичный GitHub не помещаются. URL потоков не фиксируются в коде.
