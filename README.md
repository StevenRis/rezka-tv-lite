# Rezka TV Lite · 0.2.0

Лёгкое HTML5-приложение для встроенного браузера Philips 55PUS7607/12, SAPHI,
прошивка пользователя TPN226E_V226.003.087.001. Первая версия — стенд проверки
совместимости. Это веб-закладка, а не устанавливаемое приложение App Gallery.
Каталог Rezka и воспроизведение с Rezka пока не реализованы.

## Запуск на телевизоре

После публикации откройте адрес GitHub Pages в браузере телевизора и сохраните
закладку на главном экране. Подключение к интернету требуется для первоначальной
загрузки и внешнего видео. Service Worker и офлайн-кэш намеренно не используются.

1. «Проверить пульт»: стрелки, OK, Back. Неизвестные коды видны внизу экрана.
2. При необходимости — «Настроить коды пульта», затем ↑ ↓ ← → OK Back.
3. «Тест видео» → «Тестовый MP4». Проверьте изображение, звук, паузу, полный экран.
4. «Диагностика»: сфотографируйте User Agent, кодеки и размер окна.
5. «Подключение Rezka»: запустите запрос и сравните с отдельным открытием сайта.

Коды Back 8/27/461/10009 являются кандидатами; фактические события и поведение
кнопки на SAPHI необходимо проверить на устройстве. Браузер может перехватить
Back до страницы. Home/Exit системой не перехватываются приложением.

## GitHub Pages

Создать репозиторий `rezka-tv-lite`, загрузить исходники в корень ветки `main`.
Settings → Pages → Deploy from a branch → `main` → `/ (root)` → Save.
Сборка и npm-зависимости не нужны. `.nojekyll` отключает обработку Jekyll.
HTML использует относительные пути и подходит для Pages в подкаталоге.
При устаревшей версии обновите страницу; проверьте номер версии в шапке.

## Разработка и проверки

```sh
node --check app.js
node --check navigation.js
node tests/navigation.test.cjs
```

Используются ES5-синтаксис, обычные кнопки, inline-block CSS и XMLHttpRequest.
Нет React, внешних шрифтов, аналитики, сборщика, запросов при старте или ключей API.
Индивидуальные коды пульта хранятся в localStorage; исключения хранилища обработаны.
Поддержка canPlayType — подсказка браузера, а не доказательство воспроизведения.
Проверка HLS пока ограничена canPlayType; поток HLS не тестируется.

## 0.1.1: диагностика Vewd

На тестируемом телевизоре стрелки управляют указателем, OK приходит как щелчок, Back — keyCode 8. Щелчки теперь отображаются в тесте пульта.

Кнопка «Тестовый MP4» загружает собственную синтетическую таблицу: 5 секунд, H.264 Constrained Baseline level 3.0, yuv420p, 320×180/10 fps, AAC-LC, faststart. Нажать пуск отдельно; автоматического запуска нет. Ошибки play() показывают name/message, отдельно выводятся mediaError, readyState, networkState и последние события. «Открыть MP4 напрямую» проверяет нативный проигрыватель браузера. Внешний Sintel оставлен отдельной кнопкой.

## 0.1.2: первый каталог

GitHub Actions получает настоящий каталог Rezka: проверено 11.11.2026. Ответ HTTP 200, gzip, после распаковки 522887 байт, 363 вхождения маркера карточек. Access-Control-Allow-Origin отсутствует; X-Frame-Options: DENY. С сервера разработки продолжает приходить заглушка.

scripts/catalog_probe.py извлекает максимум 24 уникальные карточки: название, краткие сведения и ссылка на страницу. Не загружает видео, не использует авторизацию, cookies, прокси или обход защиты. Workflow имеет только contents:read и выводит JSON в журнал. Подготовленный JSON публикуется отдельным коммитом в catalog.json. Планового обновления нет.

Приложение читает JSON со своего домена. Кнопка «Перечитать список» скачивает опубликованный снимок; серверная сборка не запускается. Карточки открывают оригинальный сайт. Собственное воспроизведение Rezka ещё не подключено.

На Philips пользователь подтвердил: MP4 0.1.1 воспроизводится, стрелки двигают указатель, OK работает как click, Back — keyCode 8.

## Управление цифрами (0.1.3)

2 — вверх, 4 — влево, 6 — вправо, 8 — вниз, 5 — выбрать, Back — назад. На Philips подтверждены события 50 для 2 и 53 для 5. Эти назначения включены по умолчанию и имеют приоритет над сохранённой калибровкой. Также поддержаны цифровая клавиатура компьютера и прежние стрелки. Удержание 5 не активирует следующие кнопки повторно. Встроенная подсветка следует выбору цифрами; неподвижный курсор не подсвечивает вторую карточку. При перемещении мыши включается обычное наведение. Выбранная кнопка прокручивается выше нижней панели.

Управление работает внутри Rezka TV Lite. На оригинальной странице Rezka после перехода действуют правила браузера. В фокусе тестового видео 4/6 — перемотка, 5 — пуск/пауза; 2/8 возвращают фокус к кнопкам.

## 0.1.4: backend ноутбука

Клиент notebook.js подключается к HTTPS Quick Tunnel через одноразовый шестизначный код. Случайный токен хранится только локально на телевизоре. backend.json содержит только публичный адрес туннеля, без кода или токена. Ввод цифр в полях не перехватывается навигацией.

Сейчас тестируется только фильм ID 85038 («Одиссея»). По умолчанию выбирается MP4 480p, при отсутствии — первый MP4. Видео запускается отдельно пользователем. Туннель не ретранслирует фильм. Полные URL потоков не выводятся в диагностике и не пишутся в GitHub. Живое воспроизведение с Philips через туннель ещё требует проверки.

## 0.2.0: фильмы, поиск, озвучка и качество

Нужен backend 0.3 на ноутбуке. Метаданные и потоки доступны после подключения кодом. Поиск через backend возвращает до 48 фильмов с первой страницы выдачи; исходные 24 карточки остаются стартовым снимком. Сериалы открываются на оригинальном сайте.

Для фильма загружаются озвучки, сохраняются предпочтения доступной озвучки и качества. По умолчанию выбирается наибольшее разрешение; при одинаковом разрешении приоритет MP4. HLS остаётся доступен, но его поддержка зависит от браузера телевизора. При смене озвучки/качества сохраняется текущая позиция в рамках открытого фильма; продолжение запускается пользователем.

Премиальные озвучки и качества явно отмечены, платные ссылки не выдаются анонимной сессии. Авторизация в подписочном аккаунте не реализована; для неё есть переход на сайт. Система не пытается заменять подписочные потоки или выдавать тизер за полный фильм.

Реальные воспроизведение, звук и подключение через туннель подтверждены пользователем для «Одиссеи» на предыдущей версии. Общий разбор метаданных, выбор переводов, максимального качества, поиск и позиция проходят отдельные проверки; работу новых фильмов необходимо подтвердить на телевизоре после обновления backend.
